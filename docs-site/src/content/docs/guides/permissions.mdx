# 权限与授权

小程序访问宿主能力遵循**双轨权限模型**：声明式权限写进 manifest，首次运行时向用户展示并授权；调用式授权由 API 调用触发，首次调用时弹窗征求同意。两类授权都遵循同一条公式：有效权限只收窄、不放大。

## 权限总览

| 权限 | 授权方式 | 说明 |
| --- | --- | --- |
| `wanling.api` | 声明即静默生效，无弹窗 | 不涉及用户会话数据，manifest 声明后即可调用 `wanling.request` |
| `wanling.chat.read` | 首次运行弹窗 | 弹窗文案「读取当前会话 ID（用于关联你正在看的会话）」 |
| `wanling.chat.share` | 首次运行弹窗 | 弹窗文案「向你选择的好友/群聊分享小程序卡片」 |
| `wanling.nav` | 首次运行弹窗 | 跳转动作不涉及用户数据读取，但宿主导航属可感知行为，需用户知情同意 |
| `wanling.profile` | 不在 manifest 声明，调用时弹窗 | 首次调用 `wanling.getProfile()` 时弹出，详见下文[调用式授权](#调用式授权getprofile) |

`wanling.chat.read` / `wanling.chat.share` / `wanling.nav` 在小程序**首次运行时逐项弹窗**（允许 / 拒绝），授权结果本地持久化；`wanling.api` 不弹窗，声明即生效。

## 有效权限公式

**有效权限 = manifest 声明 ∩ 用户已授权**——两个集合取交集，只收窄、不放大。

未声明或未授权时调用对应 API 会直接 reject，错误信息格式：

```
permission denied: <perm>
```

平台不做静默降级，请在 `try/catch` 中处理该错误。

## 授权生命周期

- 授权结果按小程序持久化在设备本地，同一小程序再次打开无需重新授权
- **卸载小程序即重置**：授权记录随包文件与页面存储一并清除，重装后重新走授权流程
- `wanling.chat.*` 与 `wanling.nav` 被拒绝后**持续 reject**（拒绝态持久保留）；如需重新授权，可卸载小程序后重装

## 调用式授权（getProfile）

`wanling.profile` 不占 manifest 声明、也不占首次运行的弹窗序列，由 `wanling.getProfile()` 调用触发：

- **首次调用**时弹出「身份信息授权」对话框，提示将向该小程序提供你的昵称、头像与用户标识
- **拒绝不落痕**：没有持久拒绝态，下次调用会重新弹窗
- **允许后**：后续调用直接返回身份信息，不再弹窗

`getProfile()` 返回内容的构成与 openid 的使用铁律，见[身份与用户](./identity/)。
