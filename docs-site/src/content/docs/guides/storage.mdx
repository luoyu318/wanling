# 存储与更新

## storage 按账号隔离

每个小程序运行在独立的虚拟域名下（形如 `https://<appid>.<账号段>.mini.wanling.local`），`localStorage` / `IndexedDB` 按 origin 隔离存储。隔离矩阵：

| 场景 | storage |
| --- | --- |
| 同账号 + 同小程序 | 共享 |
| 跨账号（同小程序） | 隔离 |
| 跨小程序 | 隔离 |

同一设备上切换账号，各账号的页面存储互不可见。**不要把本地 storage 当作唯一持久化依赖**——触发数据重置的场景见下文。

## 静默更新

用户打开小程序时，宿主对比服务端 `version` 与本地已装版本，不一致则自动完成更新：下载新包 → sha256 校验 → 验签 → 原子替换目录，全程用户无感，页面始终运行在最新版本的包上。

## 版本重传语义

- `version` 单调递增；同 appid 重传要求 owner 一致，重传即换版本（整包覆盖：新包字节 + 新 manifest）
- 换版本重传后，小程序状态重置为 **private** 且签名清空：已发布（published）的小程序改包后需管理员重新发布
- 重新发布前，`shareToChat` 与公共库均不可用，发布流程详见[发布上架](/docs/guides/publishing/)

## 数据重置场景

宿主升级可能变更虚拟域名的 origin 结构（例如引入账号段实现按账号隔离）。origin 一旦变化，旧 storage 不再可达，**等同数据重置**。重要数据不要只存在 localStorage / IndexedDB 里——小程序页面可直接 fetch 外部网络，应把关键数据持久化到你自己的后端，本地 storage 仅作缓存。
